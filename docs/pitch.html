Inside the engine

One engine. Any form. Add a template, not code.

01

Prepare

Straightens the photo, strips GPS and metadata. In memory only.

02

Template

The organisation's own form: fields, hints, reference lists.

03

Guard

04

Read

Open vision model on Nebius returns strict JSON.

05

Validate

Only the template's fields, in the right types.

06

Flag

Unreadable or unknown values go to a person.

Output{"records": [{"id": 1042, "signed": true, "amount": 1380}], "flags": [{"record": 0, "field": "amount", "reason": "unreadable"}]}
This is what the engine does today, in code. A template is a small JSON file: the fields to read, a hint per field and the organisation's reference lists (member IDs, order numbers). New document type means a new template, not new code. The prompt wording is plain Markdown the team can edit. The photo is fixed, stripped of location data and never stored. User notes and text in the photo can never change the rules or the output format. The model on Token Factory must return JSON in the template's schema; the engine then keeps only valid fields and types, and flags anything unreadable or not in the reference list for a person to check. Same pipeline runs the eval, so the numbers on the proof slide are the real thing.
